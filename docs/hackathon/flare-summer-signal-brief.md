# Flare Summer Signal Hackathon Brief

Source: organizer information supplied to the project on 2026-07-21. Confirm organizer updates before final submission.

## Program

Flare Summer Signal is an open online hackathon for builders creating real products on Flare. Teams may build from scratch, bring an existing project, or port an existing product to Flare.

The program has two focus areas:

1. Interoperable asset products
2. Private applications built with Flare Confidential Compute

## Required Submission Material

- Project name
- Selected bounty or bounties
- Short product description
- Target user
- Demo link, video, or working application link
- GitHub repository or technical materials
- Explanation of how the project uses Flare
- Explanation of what was newly built, ported, integrated, or improved during the program
- Smart-contract addresses or relevant deployment details, when applicable
- Short roadmap or next steps

## Encouraged Evidence

- Deployment network: Coston2, Songbird, or Flare Mainnet
- User acquisition, distribution, testing, or real-user feedback progress
- Early usage, community interest, pilot users, partner conversations, or other traction signals

These signals are encouraged rather than strict eligibility requirements. HushFlow must distinguish controlled testnet activity and simulated persona review from organic usage or external-user evidence.

## Existing Projects

Existing projects are eligible, but teams must clearly separate:

- Work that existed before the hackathon
- Work newly built during the hackathon
- Work ported, integrated, or improved on Flare
- Why the new work is meaningful to users, developers, or the Flare ecosystem

HushFlow is currently planned as new hackathon work. If any pre-existing template, library, or code is incorporated, its origin, license, and contribution must be documented.

## Judging Criteria

1. **Product usefulness:** solves a real user, developer, ecosystem, or infrastructure problem.
2. **Flare integration quality:** uses Flare meaningfully rather than superficially.
3. **Technical execution:** provides a working demo and credible, understandable architecture.
4. **Evidence of new work:** clearly shows what was built, ported, integrated, or improved during the program.
5. **Clarity and future potential:** clearly explains the product, user, integration, and credible path beyond the hackathon.

## HushFlow Submission Positioning

- Primary bounty: Confidential Compute Apps
- Secondary bounty, if dual submission is permitted: Interoperable Asset Products
- Confidential-compute evidence: encrypted seller minimum and provider quotes, custom FCC evaluation, signed result, and on-chain verification
- Interoperable-asset evidence: real FXRP-to-USDT0 RFQ settlement on Coston2
- Newly built evidence: commits, architecture decisions, FCC extension, contract deployments, test results, demo transactions, and release notes
- Distribution evidence baseline: honestly labeled simulated-persona review and automated multi-wallet Coston2 validation
